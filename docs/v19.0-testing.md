# ZoneMinder v19 acceptance crosswalk

The v19 appliance installs the ZoneMinder package provided by Debian Trixie. The source record retains the suite and installed package version, while apt verifies package integrity through Debian archive signatures.

`tests/v19.sh` checks the normal appliance path: authenticated HTTPS web and API login with the firstboot application password, including ZoneMinder's intermediate browser post-login session step and a cookie-preserving request to the authenticated Options page; creation and API readback of one non-hardware monitor; an authenticated enable-state update; MariaDB readback; persistence after a ZoneMinder restart; authenticated API deletion; and API/database absence after cleanup. It also checks Apache, MariaDB, ZoneMinder, and Postfix service state, the Adminer and Webmin HTTPS endpoints, and the supervised stable-channel updater.

## Version and update-channel basis

As reviewed on 2026-08-27, [Debian Trixie provides ZoneMinder 1.36.35+dfsg1-1](https://packages.debian.org/trixie/zoneminder), while upstream's current stable maintenance release is [ZoneMinder 1.38.4](https://github.com/ZoneMinder/zoneminder/releases/tag/1.38.4). The appliance deliberately selects upstream's official `1.38.4+trixie1` Trixie package instead of Debian's older build because it contains security fixes relevant to a network-facing surveillance service:

- [GHSA-vj5r-pc2v-gfwv](https://github.com/ZoneMinder/zoneminder/security/advisories/GHSA-vj5r-pc2v-gfwv) marks versions before 1.36.39 affected by a cross-monitor media authorization bypass and identifies 1.38.4 as patched.
- [GHSA-g66m-77fq-79v9](https://github.com/ZoneMinder/zoneminder/security/advisories/GHSA-g66m-77fq-79v9) marks the 1.36 line through 1.36.39 affected by authenticated command injection in monitor device paths and identifies 1.38.2 as the patched 1.38 floor.

The installer accepts only the exact upstream package URL and SHA256 `4828e9a0e86e2015701571cc443d37aae5e43fd4e270759c3f28463ae135f12e`, verifies signed repository metadata with fingerprint `E148DCEBF90919B49C68F056A8C670C86F88B031`, and records that provenance in the appliance. `zoneminder-update --check` remains supervised and restricts candidates to the official stable `release-1.38` Trixie channel; updates are never applied silently.

## Exact-run status

The first three exact Wave 2 executions built, imported, and completed firstboot/runtime health successfully. The first web-login check stopped on ZoneMinder's JavaScript-driven intermediate post-login page. The second preserved the authenticated cookie but requested the console, which ZoneMinder 1.38.4 correctly redirects to its mandatory first-login privacy page while `ZM_SHOW_PRIVACY` is set. The test now requests `?view=options`, an authenticated view that the upstream privacy gate explicitly exempts, and checks its stable `optionsContainer` marker without accepting or changing the privacy choice. That web flow passed in the third execution, which then exposed a monitor-fixture default-field issue: the API hydrated an invalid device default when `Device` was omitted. The fixture now sends the explicit empty value accepted by the exact 1.38.4 validator for its non-local FFmpeg monitor. All three failures are test-only defects and consume no product loop.

The historical second-failure bundle had a harness bookkeeping defect: its top-level `SHA256SUMS` named an omitted `failure-status.txt`. ## Deferred boundaries

Camera capture and motion detection require hardware or a representative media stream, so the bounded acceptance fixture uses a disabled FFmpeg monitor. The test proves authenticated monitor management without claiming hardware capture coverage.
